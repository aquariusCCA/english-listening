# 規則維護檢查清單

修改 CLAUDE.md、rules/ 或 `.claude/commands/` 的指令檔時：

- 動手前先讀磁碟上的現況全文，不憑對話中的記憶；先 git pull 再讀（CLAUDE.md〈Git 工作流程〉）。
- 改動跨檔出現的名稱（指令名、規則檔名、章節名、卡背標籤名「例／影片／補充／注意」、表格欄位名）時，用 grep 找出所有出現處，同一次全部改完——本專案的跨檔引用全是純文字，改名沒有工具會替你抓漏。**指令名另外出現在 README.md 的「製卡流程」表格**：那份重複是刻意的（README 是 GitHub 入口與換電腦時的操作說明，只給連結達不到目的），代價就是改指令名時務必連它一起改。
- 跨檔引用規則檔的小節時用名稱、不用編號——編號會因增刪位移而無聲指錯（grammar-in-charts 的實證教訓：一次步驟對調斷了四處引用）。
- 改完以改動涉及的關鍵詞 grep 整個規則範圍（CLAUDE.md、rules/、`.claude/commands/`、README.md），確認沒有殘留舊稱呼，也沒有與既有規則矛盾。
- **不設 CHANGELOG**：規則沿革看 git log 即可——commit message 依規格已寫明「改了什麼、為什麼」，另開檔案就多一處要同步維護的地方。這是與 grammar-in-charts 刻意不同之處，請勿好心加回去。
- 不限改規則時：發現產出物偏離規格（CSV 格式走樣、README 卡片數不符、逐字稿 frontmatter 缺欄位），當場修正並在 commit 訊息註明，不留著爛。
